BIOATLAS PH — BUILD IT STEP BY STEP

Start by running the website using README.md. Keep the browser and source
files side by side. This is a working learning scaffold: understand and adapt
each section, rather than submitting unfamiliar code.

STEP 1: UNDERSTAND THE TWO PAGES
Open index.html. Find header, nav, main, section, article and footer.
The portfolio explains the purpose, introduces Jeff and links to app.html.
Open app.html. This page stays loaded while search results change, making
the main application a single-page experience without a framework.
Practice: change the portfolio introduction in your own words.

STEP 2: UNDERSTAND THE DESIGN
Open styles.css. The :root variables define paper, text, green and borders.
Shared classes style both pages. Grid places the record list beside the map.
Media queries turn this into a map/list switch on narrow screens.
Practice: locate the mobile breakpoint and explain what changes there.

STEP 3: FOLLOW A SEARCH THROUGH JAVASCRIPT
In script.js, follow this path:
form submit -> readFilters -> validateYears -> runSearch -> buildParams
-> fetchJSON -> normalizeRecord -> renderResults -> renderMap

Example parameters:
country=PH
hasCoordinate=true
hasGeospatialIssue=false
taxonKey=212 (birds)
year=2020,2024
limit=60
offset=0

The API returns JSON. Its count is the matching-record total, while results
contains only the requested page. The website must not confuse those values.
Practice: open your browser's Network panel and inspect an occurrence request.

STEP 4: UNDERSTAND SPECIES AND LOCATION
The species suggestion endpoint returns taxon identifiers. Choosing a result
keeps its identifier so the occurrence endpoint can filter by that taxon.
A typed scientific name is validated separately; fuzzy matches are not silently
substituted. Group buttons use verified GBIF identifiers for broader taxa.

GBIF geometry expects longitude followed by latitude. Leaflet marker positions
use latitude followed by longitude. This order difference is easy to get wrong.
Practice: compare geometry() with the L.marker call in renderMap().

STEP 5: HANDLE IMPERFECT DATA
normalizeRecord keeps absent coordinates as null. A missing coordinate must
not become zero, which would plot a misleading point. Missing dates, photos,
licences and names get honest labels. Source text is inserted with textContent,
not parsed as HTML. URLs are restricted to HTTP/HTTPS.
Practice: inspect a detail dialog and explain coordinate uncertainty.

STEP 6: HANDLE FAILURES AND RAPID SEARCHES
fetchJSON checks response.ok because fetch does not throw for every HTTP error.
runSearch uses try/catch/finally to handle errors and restore controls. An
AbortController cancels an earlier request. A request number prevents old
responses overwriting new results. A timeout prevents an endless spinner.
Practice: use browser offline mode, search again, then reconnect and retry.

STEP 7: SAVE A SHORTLIST
saveRecord writes a compact public record snapshot into localStorage using
JSON.stringify. readSaved restores it with JSON.parse. This persists between
page reloads in the same browser, but it is not shared across devices.
Practice: save a record, reload, inspect the shortlist, then remove it.

STEP 8: CHECK BEFORE PRESENTING
1. Search a full scientific name such as Lanius schach.
2. Combine a location and year range; explain that regions are approximate.
3. Change pages and show how the map changes with the loaded page.
4. Open a record and follow its original source and photo credit.
5. Save a record and show it after a reload.
6. Demonstrate invalid years, no results, and a connection failure.
7. Show the mobile map/list switch.

PRACTICE QUESTIONS
- What is an API and why is GBIF useful here?
- Why do we use await twice (fetch and response.json)?
- What is the difference between a taxon and an occurrence?
- Why is the result count different from the number of map pins?
- Why does no record not prove no species is present?
- Why are coordinate order, missing fields and data attribution important?
- What does localStorage keep, and when can it be lost?
- Which code belongs to the application and which comes from map libraries?
